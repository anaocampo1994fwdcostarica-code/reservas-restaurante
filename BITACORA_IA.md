# Bitácora de uso de IA

Ana María Ocampo utilizó IA como copiloto durante el desarrollo de este proyecto. La IA se usó para proponer estructuras, explicar alternativas, detectar errores y apoyar ajustes de interfaz. Ana revisó, comprendió, integró y probó el código antes de incorporarlo; además, configuró PostgreSQL, probó los endpoints, configuró n8n y verificó los resultados obtenidos.

| Etapa | Prompt o solicitud realizada a IA | Aporte recibido | Validación o corrección realizada por la estudiante |
| --- | --- | --- | --- |
| 1. Estructura inicial | Solicitud de una estructura para un sistema de reservas con React, Node.js, Express y PostgreSQL. | Propuesta de separación entre `backend`, `frontend`, `schema.sql`, `docs` y `n8n`, con rutas, controladores y servicios. | Ana contrastó la estructura con el enunciado y organizó los archivos en el repositorio. |
| 2. Modelo relacional | Solicitud de apoyo para definir mesas, clientes, reservas y horarios, con relaciones y restricciones. | Sugerencias de claves, campos obligatorios y restricciones de capacidad, estados y horario. | Ana revisó el modelo y ejecutó `schema.sql` en PostgreSQL, verificando tablas y datos de ejemplo. |
| 3. API por capas | Solicitud de guía para organizar una API Express con `routes`, `controllers`, `services` y PostgreSQL. | Ejemplos de responsabilidades por capa, `pg.Pool` y rutas REST. | Ana revisó imports, nombres de archivos y respuestas HTTP; configuró credenciales locales y probó la API. |
| 4. Imports y rutas | Solicitud para diagnosticar errores de importación, exportación y rutas relativas. | Explicación de módulos ES, rutas relativas y exportaciones. | Ana corrigió las referencias necesarias y comprobó que el servidor iniciara sin errores de módulos. |
| 5. Reglas de reservas | Solicitud de apoyo para validar capacidad, horarios, cruces, estados y ausencias. | Propuestas de validaciones, consultas parametrizadas, transacciones y códigos 400, 404 y 409. | Ana verificó las reglas mediante endpoints y revisó que los mensajes fueran comprensibles. |
| 6. Frontend React | Solicitud de apoyo para distribuir páginas, componentes, servicios y hooks. | Recomendaciones para formularios controlados, carga/error y componentes reutilizables. | Ana integró el frontend y comprobó navegación, formularios, filtros, ordenamiento y detalle de reservas. |
| 7. Chatbot con n8n | Solicitud de guía para conectar el frontend a un webhook local con un contrato de respuesta definido. | Propuesta para centralizar la llamada al webhook y manejar errores de red, HTTP y contrato inválido. | Ana configuró y probó n8n localmente. Debe exportar el flujo real antes de entregar, según `n8n/INSTRUCCIONES_EXPORTAR_WORKFLOW.md`. |
| 8. Diseño y accesibilidad | Solicitud de ajustes para navegación superior, identidad de La Casona de Laly, contraste y diseño responsive. | Sugerencias de jerarquía visual, paleta, etiquetas y adaptación para pantallas pequeñas. | Ana revisó visualmente las pantallas, ajustó la identidad del restaurante y verificó el comportamiento móvil. |
| 9. Validación final | Solicitud de una lista de comprobación antes de entregar. | Recomendaciones para `npm run lint`, `npm run build`, endpoints y pruebas visuales. | Ana ejecutó validaciones del frontend, probó endpoints y realizó pruebas visuales. Las capturas requeridas se listan en `docs/EVIDENCIAS.md`. |
